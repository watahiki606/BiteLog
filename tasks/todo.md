# #184 店名や商品名を入れたら、公式の栄養成分を探して写真解析に使う

チェーン店の料理は写真だけだと大きく外れる。12品の公式カロリーに対し、平均誤差は54〜89%だった。
店名とメニュー名を渡してWeb検索させると13%になった。店名なしでも常に検索させると、費用が約10倍になる。
そのうえ店を決めつけて調べる誤りも出たので、検索は名前が入っているときだけにする。

決めたこと
- 「お店・商品名」はメモ欄とは別の欄にする。メモ欄は量の補足に使う
- 名前があれば、フードマスター、公式サイトの順に探す
- フードマスターは他のユーザーの項目も探す。ブランド名が「AI」の推定値は除く
- 検索ありの解析は推論lowにする。評価では誤差13%、±20%以内30/36、1000回で約2400円、平均6.6秒だった
- 名前が空なら今と同じ。写真から推定し、検索はしない

## レビュー

- 評価は本番案で行った。推論lowで、名前は専用の欄から渡す。正解は各チェーンの公式カロリー
  - チェーン12品に名前を渡すと、検索なしは誤差58%、±20%以内12/36。本番案は誤差14%、31/36。1000回で2273円、平均6.9秒
  - 成分表示7枚に名前を渡しても21/21。3回に1回は検索するが、値は成分表示のまま
  - 出典は返答の本文に付かない。`include` で検索したページの一覧を受け取り、モデルが書いた URL がその中にあるときだけ返す。11件中10件が一覧にあった
- 残る誤り
  - サーモンアボカドにメモ「1貫だけ」を付けても、7回中2回は2貫分の140kcalを返した。結果画面で直せる
  - カラマリは公式値どおり193kcalでも、根拠を「推定」と答えることがある。表示は控えめな側に倒れる
  - 検索結果に公式に似せたドメインが混ざる。`akindo-sushiro-jp.pro` など。結果画面ではドメインを見せる
- 範囲外で見つけたこと: 通常の検索画面で、使ったことの無い食品を選ぶと前回量1で記録される。100gの食品なら1g。今回は候補画面だけ1食分にした
- 確認
  - Worker 80件、iOS のユニットテストが通過。web と docs のビルドも通過
  - `wrangler dev` に実写真で確認した。名前あり、量のメモあり、成分表示、名前なしの4通り
  - 画面は、一時テストで写真選択、候補、結果の3通りを画像にして確かめた。iPhone SE の高さにも収まる
- 評価に約9.5ドル使い、OpenAI のクレジットを使い切った。lessons に記録した

## 見直し後の振り返り

- 実機で、店名を先に入れる形を試すと、長い商品名で登録済みの食品に当たらなかった。D1 の LIKE パターン長の上限で SQL がエラーになり、アプリは黙って Web 検索へ進んでいた。instr に変えて直した
- 店名を先に入れさせると、調べない人にも入力欄が増える。結果画面から調べ直す形にし、名前の欄には写真のロゴや文字から読み取った見当を入れておく
  - 見当はチェーン17枚のうち、スシロー、くら寿司、ローソンの写真でだけ出た。ロゴの無いすかいらーく系は空
  - 成分表示7枚を5回ずつ解析し、見当つきでも 35/35。見当なしも 34/35 で、チーズの個数の取り違えはぶれ
- 結果画面の候補は、他の人の項目と AI の推定値も含めて探す
- 実機で、見当の入った欄から調べ直す、ロゴの無い写真、ロイヤルホストのサラダの候補を確かめた
- チェーン店の公式値を D1 に貯める件は #186 に分けた
