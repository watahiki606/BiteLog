# iOS の栄養素の値と表示を定義ファイルから回す

設計は `~/research/bitelog-nutrients/design.md` の2-4と、7章の PR 4。見た目と通信の形は変えない。

## 計画

- [x] 作り直しの前に、JSON の形を押さえるテストを足す。5つの栄養素に別々の値を入れる
  - 食品の読み書き、必須の栄養素が欠けた食品、スナップショット、作成と更新の本文、記録の按分、日ごとの集計、日次の統計
- [x] `NutrientAmounts` を作る。キーが無いことを不明とし、JSON は平らなキーで読み書きする
- [x] 食品、作成と更新の本文、スナップショット、計算済みの値、日ごとの集計、日次の統計を `NutrientAmounts` で持つ。今のプロパティ名と初期化の引数は残す
- [x] 表示名、短い名前、単位、桁数、読み上げの単位を定義から引く。色とアイコンは `NutrientID` の拡張に置く
- [x] 使わなくなった短い名前のキーを Localizable.strings から外す
- [x] iOS の単体テストを全件通す
- [x] デザインギャラリーを main とこのブランチで英語と日本語で描き出し、見た目が同じことを確かめる

## 振り返り

- 炭水化物は糖質と食物繊維の合計で、定義ファイルには無い。`Nutrient` は画面に並べる栄養素の型として残し、定義にあるものは `NutrientID` から引くようにした
- `NutrientTotals` は、値の分からない品を数える型。最初の5項目は必ず値があるので、使う場面が出る PR 8 で足す
- 計算済みの値の足し算は、片方でも不明なら結果も不明にした。不明を 0 として足さないため
- ギャラリーの24枚のうち20枚はバイト単位で同じだった。残る4枚は行に出る時刻が、描き出した時刻の1分の差でずれていただけだった
