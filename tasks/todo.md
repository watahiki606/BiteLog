# iOS アプリの UI/UX 改善（第2ラウンド）

「より見やすく、使いやすくしたい」の続き。今回は最初に
「世の中の優れたアプリのデザインは iOS 標準に準拠した結果なのか」を調べ、
その答えから作業の範囲を決めた。

## 調査：優れたアプリは「標準に準拠した結果」なのか

答えは **違う。ただし「標準を外した結果」でもない。層が分かれている。**

Apple Design Awards 2026 の評価文には「HIG に準拠している」という言葉が
一度も出てこない。褒め言葉は2種類に割れる。

- **中身の表現**：Tide Guide「custom animations」「空の色に合わせたパレット」、
  grug「落書き風の完全自作ビジュアル」、Moonlitt「best-in-class Liquid Glass
  integration と easy onboarding」
- **標準の仕組みを使い切ったこと**：Inclusivity 受賞の Guitar Wiz は
  「VoiceOver / Dynamic Type / Increased Contrast / Differentiate Without Color 対応」

実務側の見解も一致している。標準コンポーネントを自作に置き換えると
VoiceOver・状態変化・ハプティクス・Dynamic Type 追随を全部作り直すことになり、
たいてい劣化する。これは第1ラウンドで BiteLog 自身が踏んだ道でもある。

> 標準は**土台**。差は**中身の見せ方**で出す。
> 優れたアプリは「準拠したから良くなった」のではなく、
> 土台を標準に任せたぶんの労力を中身に注げた。

出典:
- https://developer.apple.com/design/awards/
- https://developer.apple.com/design/human-interface-guidelines/
- https://developer.apple.com/documentation/TechnologyOverviews/adopting-liquid-glass

## 方針（ユーザー確認済み）

- A. 土台に残っている穴を塞ぐ（標準に合わせるだけ。自作の余地がない）
- B. 中身の見せ方で差を出す（栄養データの読ませ方）
- 言語切替の `exit(0)` は廃止してよい
- 広告バーの位置・見た目は調整してよい（表示頻度と掲載面は変えない）

## レビュー

コミットは4本。土台 → 中身 → 実画面で見つかった分、の順。

1. `8b40148` 通信の失敗を黙って飲み込まない
2. `2fc9c9d` OSが用意している仕組みに乗り切る
3. `9943762` 栄養データを読める形にする
4. `16cde90` 実画面でしか出ない崩れを直す

### 直した実害

- 編集を保存できなくてもシートが閉じ、保存したつもりになれていた
- 食品一覧・追加シートが通信失敗時に「1件も登録されていません」と出ていた。
  登録済みの食品を作り直す操作に直結する
- その日のログの読み込みに失敗すると「何も食べていない日」に見え、
  二重記録を誘発していた
- 食品の削除が失敗しても行を戻さず、消えたように見えて消えていなかった
- 目標値の保存で PUT が4本並走し、最後に返った応答で他の3つが巻き戻りえた
- 追加シートは行タップで即保存なのに取り消す手段が無かった
- `accessibilityReduceMotion` / `colorSchemeContrast` がコード中に1件も無かった
- 統計の PFC バランスが `.blue` / `.yellow` / `.green` 直書きで、
  `Nutrient.swift` が「白背景でコントラストが足りない」と書いている当の色を使っていた
- 言語切替でアプリを `exit(0)` で落としていた

### 実画面でしか出なかった分（コミット4）

部品単体の描画では出ず、モックAPIで通して初めて分かったもの。

- 追加シートの読み込み失敗が無言だった
- 広告の地が高さぶんしか無く、タブバーの裏で行が見切れていた
- スクロールできるグラフでは標準のタップ選択がスクロールに吸われる
- 吹き出しの半透明材質が下の折れ線の色を拾う
- 設定の言語の行だけラベルまで着色されていた
- AX5 で統計画面が読めない（目盛りが重なる・日付が切れる・期間が3行）
