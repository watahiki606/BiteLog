# 新しい栄養素をカードにし、基準値に対する割合をリングで見せる

ブランチ feat/nutrient-cards-reference。push と PR はしない。

## いま基準値を出している所

- 統計の「その他の栄養素」カード。1日平均の値の下に「目標量 7.5g 未満」「推奨量 650mg に対して 82%」「目安量 9.0µg」と文で出す。超えた、届いたの見た目は無い
- 統計の「食事の質スコア」。栄養素ごとに基準に対する割合を文で出す
- 1日の合計、記録の編集、食品の詳細には出していない。1日の合計の主要な栄養素の棒は、目標の設定の値と比べている

## 計画

- [x] 基準値と比べた結果を出す型をテストから作る。上限の目標は超えたら超過、満たしたい栄養素は届いたら到達。飽和脂肪酸はエネルギーの割合から g に直す
- [x] 栄養素ごとの記号と色。ミネラルは元素記号、ビタミンは A、D、C のような記号。色は今の配色とぶつからない色を Asset Catalog に足し、コントラストを確かめる
- [x] リングのカードと2列の並び。ミネラル、ビタミン、脂質の見出しで分ける
- [x] 1日の合計の「その他の栄養素」をリングのカードに。基準値はプロフィールの性別と年齢から引く。プロフィールが無ければ値だけ
- [x] 統計の「その他の栄養素」と「詳しい栄養素」をリングのカードに
- [x] 記録の編集と食品の詳細の行を、記号入りの丸をつけたカードの行にそろえる
- [x] 日本語と英語の文言
- [x] テストを流し、失敗0件を確かめる。描画ギャラリーでライトとダーク、標準と AX5 を見る
- [x] 実機の iPhone 17 Pro に Debug で入れる

## 振り返り

- 途中で「棒グラフではなくリングに」と指示が変わった。新しい栄養素は、記号の丸の外周に割合だけ伸びるリングのカードにした
- 1日の合計で、飽和脂肪酸の目標量は目標のカロリーに 7% を掛けて g に直した。その日に食べたエネルギーで割ると、朝の1品だけで超過になる。統計では期間に食べたエネルギーの1日平均を使う
- 女性の鉄は月経なしの推奨量でリングを描き、月経がある場合の値をカードに添えた
- 目安量のビタミン D なども、ほかと同じくリングと割合を出した。以前の設計では目安量は割合を出さないとしていたが、今回の指示に合わせた
- 1日の合計は「食塩と飽和脂肪酸」「ミネラル」「ビタミン」の見出しにした。定義のまとまりのままだと、食塩がミネラルに入って2列の半端な空きが3つできた
- 食物繊維の棒は今までどおり、目標を超えると赤になる。満たしたい栄養素としては新しいカードと扱いが違う
- テスト: iOS の単体テスト 313件通過、失敗0件。main の304件に、基準値と比べる型の9件を足した数
- 実機の iPhone 17 Pro に Debug で入れて、起動と1日の合計の表示を確かめた。開いた中身は描画ギャラリーのライトとダーク、標準と AX5 で見た

# 品数の表示を外し、詳しい栄養素を1日の合計にも出し、5つの栄養素を足す

## 計画

- [x] 「何品中何品の値から」を iOS のカードと web の食事ログから外す。使わなくなった文言と `isComplete` も消す
- [x] 1日の合計に、統計と同じ畳んだ「詳しい栄養素」を同じリングのカードで出す
- [x] ヨウ素、セレン、クロム、モリブデン、ビオチンを、定義、基準値、D1 のマイグレーション 0006、Worker、iOS に足す。web は定義から回るので変更なし
- [x] 成分表の SQL を作り直し、5つの値がある行を数える。未測定は null のまま
- [x] テストの失敗件数を確かめる

## 振り返り

- 並びは定義の順がどの画面でも表示の順になる。5つを定義の末尾に足すと、見出しで分けたカードと編集の行で順がずれるので、ミネラルはマンガンのあと、ビオチンはパントテン酸のあとに入れた
- CSV の書き出しの列も定義の順なので、足した栄養素の列の中で位置が変わる。取り込みは見出しの名前で列を探すので読める
- 成分表で値がある行: ヨウ素 1361、セレン 1374、クロム 1366、モリブデン 1359、ビオチン 1366。2538行のうち、ヨウ素の3行は「*」だけのセルで分からないにした
- テスト: iOS 314件、Worker 186件、web 59件、いずれも失敗0件
