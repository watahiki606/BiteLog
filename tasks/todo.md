# #184 店名や商品名を入れたら、公式の栄養成分を探して写真解析に使う

チェーン店の料理は写真だけだと大きく外れる。12品の公式カロリーに対し、平均誤差は54〜89%だった。
店名とメニュー名を渡してWeb検索させると13%になった。店名なしでも常に検索させると、費用が約10倍になる。
そのうえ店を決めつけて調べる誤りも出たので、検索は名前が入っているときだけにする。

決めたこと
- 「お店・商品名」はメモ欄とは別の欄にする。メモ欄は量の補足に使う
- 名前があれば、フードマスター、公式サイトの順に探す
- フードマスターは他のユーザーの項目も探す。ブランド名が「AI」の推定値は除く
- 検索ありの解析は推論lowにする。評価では誤差13%、±20%以内30/36、1000回で約2400円、平均6.6秒だった
- 名前が空なら今と同じ。写真から推定し、検索はしない

## 計画

- [ ] 評価: 本番用のプロンプトで測る。名前は欄から渡す。チェーン写真で次の3つを各3回
  - 名前だけ
  - 名前と量のメモ。例: サーモンアボカドに「1貫」
  - 成分表示の写真に名前を入れた場合。21/21 を保つか
  - 出典URLが、返答の形式指定と一緒に返るか確かめる。url_citation
- [ ] Worker `aiAnalyze`: Responses API に移す。TDDで進める
  - 検索なしも同じ道を通す。評価では Chat Completions と同じ精度・費用だった。21/21、44円
  - `menuName` があれば web_search ツールと推論lowを使い、検索用の指示を足す
  - レスポンスに `basis` と `sources` を足す。basis は label、official、estimate のどれか。sources は title と url
  - `menuName` を送らない古いアプリは、今と同じ動きのままにする
- [ ] Worker `foodMasters`: 名前で探す口を作る。TDDで進める
  - 空白で語に分け、すべての語がブランド名か商品名に含まれるものを返す
  - ブランド名「AI」は除く。並び順は今と同じく、使った回数の多い順
- [ ] iOS
  - 写真選択の画面に「お店・商品名」の欄を足す。欄の下に「入力すると公式の栄養成分を調べます」と書く
  - 名前があれば、まずフードマスターを探す。見つかれば候補を出し、選ぶだけで記録できるようにする。「この中にない」を選ぶと公式サイトを調べる
  - 検索中は「公式サイトを調べています」と出す
  - 結果画面に根拠を出す。公式サイトの値なら出典のリンクを、写真からの推定ならそう書く。名前が空だったときは「お店の名前を入れると公式の値を調べます」と案内する
  - DTOと、英語・日本語の Localizable.strings
- [ ] テスト: `cd cloudflare && npm test`、iOS は xcodebuild で
- [ ] 確認: `wrangler dev` とシミュレータで、次の3通りを動かす
  - チェーン写真に名前を入れる
  - フードマスターにある名前を入れる
  - 名前を空にする
- [ ] PR。`gh pr diff` で確かめてから説明を書く
