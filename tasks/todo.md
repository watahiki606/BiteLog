# 国の食品成分表の食品を、ふつうの食品として登録する

同じ PR #238。本番 D1 への書き込み、Worker と web のデプロイ、マージ、申請はしない。

## 方針

- composition_foods の 2,538 食品を food_masters に入れる。100 g あたり、名前は一覧のまま、ブランド名は空
- 作った人は `composition`。編集と削除は管理者だけ。食品番号は既存の列 nutrient_source_ref に、出典は composition_table に入れる。新しい表と列は作らない
- id は食品番号から決める。同じ食品はどの環境でも同じ id になり、取り込み直しは上書きになる
- 基本5項目の未測定は 0 にする。食物繊維 144 件、タンパク質と脂質 1 件。food_masters の基本5項目は NULL を持てない
- 写真の解析は food_masters の国の一覧の食品から食材を引く。composition_foods は 0008 で消す
- 食品検索は、使ったことのある食品、自分の食品、ほかの人の食品、国の一覧の食品の順。成分表の書き方に寄せる言い換えは食品検索に移す
- 食品の入力の「似た食品の値を入れる」と、成分表を探す API を消す。iOS と web

- [x] Worker: 写真の解析の食材を food_masters から引く。/api/composition-foods を消す

- 手元の D1 に 0006〜0008 を当て、適用前の composition_foods と比べた。2,538 食品すべてが値、id、名前、単位とも一致。food_masters は 18,091 → 20,629
- 直した取り込みスクリプトで公開の Excel から SQL を作って流すと、行は増えず、id、名前、基本5項目は一致。違ったのは手元の D1 が古かった列だけ（0006 の5列、脂質 0 の飽和脂肪酸 180 件）。本番はこれらが入った状態なので、0008 だけで同じ値になる
- 本番は読み取りだけで確かめた。composition_foods 2,538、飽和脂肪酸 2,147、ヨウ素 1,361、ぶつかる id と unique_key 0、未適用のマイグレーションは 0008 だけ
- テスト: Worker 171件、web 54件、iOS 310件。どれも失敗0件。減ったのは成分表から選ぶ機能のテスト（web 6件、iOS 9件）を消したため
