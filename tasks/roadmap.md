1. **嘘と壊れを先に止める** — 公開中の誤りと、データが静かに壊れる箇所

## 体組成計まわりの申し送り

プロトコルの仕様は **#146** と `BiteLog/Utilities/TanitaProtocol.swift`。
`.pklg` の解析は `tools/pklg-decode.py`。

### 前提（読まずに実装すると必ずはまる）

- **フレームの3バイト目は通し番号ではない。** そのメッセージの最後のフレームの位置
  （1フレームなら 0、3フレームなら 2）。通し番号として送ると、体重計は来ないフレームを
  待ち続けてタイムアウトし、`Err` を表示して切断する
- **名乗りの応答の2バイト目を見ること。** 0 以外は「その識別子を知らない」。
  体重計の表示は `Err UUID` になる。ここを見ずに次へ進むと、原因が
  「通信中に切断されました」としか分からなくなる
- **ボンドはアプリをまたぐ。** iPhone が体重計とボンド済みなら別のアプリからも購読できる。
  ペアリングを奪う必要は無い
- **個人データの書き込み（`10 02`）は飛ばしてよい。** 読むだけで測定に進める
- **つなぐときは体重計の電源が入っていない状態で。** 起こしてから接続しようとすると見つからない

### いまの状態

いま動いているのは、**公式アプリが登録した識別子を借りている**状態。
値は端末の `UserDefaults`（キー `TanitaAppIdentifier`）に入っている。
リポジトリにも issue にも書かないこと。

この借り物には2つの弱点がある。#154 で自前の登録に移すまで残る。

- 公式アプリを再登録すると識別子が変わり、動かなくなる
- 他の人は借りるものを持っていないので、一般公開しても誰も使えない

### 実機で試す手順

シミュレータに Bluetooth は無いので、体組成計まわりは実機でしか確かめられない。

```
# 接続中の端末を確認
xcrun devicectl list devices

# 端末向けにビルド
xcodebuild -project BiteLog.xcodeproj -scheme BiteLog -configuration Debug \
  -destination "id=<xcodebuild の device id>" -allowProvisioningUpdates build

# 転送
xcrun devicectl device install app --device <devicectl の device id> \
  <DerivedData>/Build/Products/Debug-iphoneos/BiteLog.app
```

取り込み画面に「通信の記録」が出る。送受信したコマンドと応答の中身が並ぶので、
どの段階で止まったかはそこで分かる。Debug ビルドでは識別子の差し替え欄も出る。

## 本番データを触るときの線引き

`tasks/lessons.md` の「本番データを分析したら、出力先ごとに線を引く」を読むこと。
件数や割合は外に出してよい。個票（誰が何をいつ食べたか、測定値そのもの）は
ターミナルの中だけ。テストやコメントの例示に実在の記録を使わない。
